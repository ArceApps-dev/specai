Execute the canonical SpecAI flow exactly:

grounding → grill-me → write-prd → approval → six documents → choose implement/backlog → branch only if implement → per-task cycle → spec-compliance-reviewer → verifier → HTD de aceptación → Gate UA → finishing

Ground the codebase before asking one question at a time with grill-me. Write and approve the PRD, then create the six documents without a branch. Choose implement or backlog: backlog keeps the feature folder and creates no branch; create the feature branch only if implementation is chosen. Before implementing each task, preflight scripts/agent-harness-contract.json and dispatch through the active native harness: OpenCode delegate, Codex spawn_agent/wait_agent with multi_agent = true, or Antigravity invoke_subagent. Use a fresh session with fork_context: false and only its bounded task context; record Max Runtime: 900 seconds, Deadline: 900 seconds, Heartbeat every 30 seconds, and Poll interval: 15 seconds. A missing capability is TASK_BLOCKED: never execute inline or use a silent fallback. Then record TASK_STARTED with timestamp, branch, git_hash, task_id, and context. For every implementation task, run implement → build/test → code review with quality and Compliance verdict: PASS → commit → document. Between sessions, recover from *-tasks.md and the Execution Log of *-plan.md: restore every in_progress task, or the first eligible pending task when none is active; block on inconsistencies. If a wait returns timed_out, retain the handle and poll again; do not relaunch. TodoWrite is only the session mirror. Human approval and review checkpoints remain decision gates, never session persistence. After all tasks, run the full suite, spec-compliance-reviewer for cross-task/global invariants, then verifier against _verify.md. Immediately after verifier PASS and before asking for acceptance, present a short HTD de aceptación grounded in verified current-HEAD facts: include Artefacto / arranque with the exact install/open/run command or why manual launch is not applicable; a prioritized list of changed visible/behavioral scenarios, each with Ruta, Acción, and Esperado; No hace falta probar only for explicitly out-of-scope or already-covered items; and a final request to test this HTD de aceptación and reply accept/acepto or report an issue. Never invent paths or expected behavior; if a fact is unavailable, state that manual verification is blocked or ask for the missing detail. Record Gate UA HTD: presentado and HTD presentado with timestamp in the Execution Log, then record the acceptance timestamp and exact text. No se puede pedir `accept` before presenting the HTD de aceptación; missing/negative/ambiguous responses require clarification or iteration. Only after the user tests the HTD and explicitly accepts may finishing begin. The controller owns the todo; specai-documentation owns living-document states, checks, and logs; internal steps are never marked.
